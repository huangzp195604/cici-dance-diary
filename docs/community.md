# 社区治理：公约、举报、约练安全

公开推广前的三件护栏。核心思路：**规则要能被执行，不能只是姿态。**

## 1. 社区公约

`src/utils/community.ts` 的 `COMMUNITY_RULES`，六条，每条都写成可执行的动作而不是口号：

| # | 条目 | 落到哪 |
| --- | --- | --- |
| 1 | 只聊舞蹈，不做生意 | 广告 / 带货 / 招代理 |
| 2 | 钱和群都走站内 | 对应举报原因里的「站外收款」 |
| 3 | 见面只在公共场所 | 对应「虚假约练」与报名安全确认 |
| 4 | 不替别人公开隐私 | 对应「泄露他人隐私」 |
| 5 | 不骚扰、不攻击 | 对应「人身攻击 / 骚扰」 |
| 6 | 看到违规就举报 | 指向帖子与回复右上角的入口 |

入口三处：论坛筛选栏的「公约」按钮、发帖弹窗底部「发布即表示同意社区公约」、游客预览页底部。

**不做强制勾选。** 记录类产品的门槛已经够高，再拦一道只会劝退；做法是摆在看得见的地方，随时能打开。

`COMMUNITY_ENFORCEMENT` 写明处理梯度（删除 → 限制发帖与私信 → 封号），规则才有重量。

## 2. 举报

### 数据层

云端表 `content_reports`（RLS 已开）：

| 列 | 说明 |
| --- | --- |
| `owner_id` | 举报人，`DEFAULT auth.uid()`，客户端不能伪造 |
| `target_type` / `target_id` | `thread` / `reply` / `message` / `profile` + 目标 id |
| `target_author_id` | 被举报内容的作者，便于按人聚合处理 |
| `target_excerpt` | 内容摘要，后台不用翻原文就能判断 |
| `reason` | CHECK 约束限定七个值，防止前端乱传 |
| `status` | 默认 `open`，处理时改 |

策略：`SELECT` 仅本人可读自己的举报（举报人信息不外泄），`INSERT` 仅 `owner_id = auth.uid()`，**没有 UPDATE / DELETE**——举报一旦提交就不能撤回或篡改。唯一索引 `(owner_id, target_type, target_id)` 防止重复举报。

查看待处理举报：

```sql
SELECT id, created_at, reason, target_type, target_id, target_author_id, target_excerpt, detail
FROM content_reports WHERE status = 'open' ORDER BY created_at DESC
```

### 界面层

- 帖子右上角、每条回复的时间戳旁各有一个小旗子。**自己的内容不显示**（举报自己没意义）。
- 七个原因带具体说明（「站外收款：发收款码、要求加微信转账、绕开官方报名」），不写「违规内容」——用户才知道该选哪个，你也能据此判断优先级。
- 弹窗里明确写「被举报者不会收到通知，举报人信息只有平台能看到」，否则没人敢点。
- 提交后给出处理承诺（24 小时内核实、涉及转账骚扰优先），不是一句「已收到」。
- 提交后**立即在本机折叠该内容**，保留「仍要查看」出口。不做无声删改。

### 失败降级

`src/services/reportApi.ts`：上云失败（未登录 / 网络异常）时写进本机队列并**如实告知**「记录已保存在本机，登录后会自动补传」，不假装成功。`flushReports()` 用于补传。

## 3. 约练安全提示

两层，各管一件事：

- **常驻一行**（约练卡片内）：`MEETUP_SAFETY_SHORT`——首次见面选营业中舞室，把时间地点告诉一位朋友。没报名的人也该看到。
- **首次报名确认**（弹窗）：`MEETUP_SAFETY_CHECKS` 三条具体动作——地点选公共场所、出发前告诉一个人、钱只走站内报名。

只在这台设备上确认一次（`cici_meetup_safety_ack_v1`），之后报名不再弹。每次报名都弹的免责声明会被无脑点掉，最后谁也没看。

## 验证

`tsc` + build 通过；真实 Chrome 375px **18/18 PASS，0 控制台报错**：公约六条齐全、他人帖子有举报按钮而自己的没有、七个原因齐全、提交有结果、举报后本机折叠且保留展开、约练卡片有安全提示、首次报名弹确认、确认后完成报名。游客态另测：预览页可见公约入口且能打开。
